Help Center

Kurzanleitungen fuer die wichtigsten Operator-Workflows. Jede Sektion zeigt dir den Zweck, wo du klicken musst und eine klare Schrittfolge.

1Wo lege ich meine Verbindungen (API-Keys, OAuth) an?

Alle Zugaenge liegen gebuendelt in Connections. So bleiben Keys zentral, versionierbar und fuer Routing-Logik verfuegbar.

Screenshot Placeholder: Dashboard → Tools → Connections
Provider-Liste mit Status, Key-Feldern und OAuth-Buttons
  1. Im Dashboard links auf Connections gehen.
  2. Provider auswaehlen (z. B. OpenAI, Anthropic, GitHub, Google).
  3. API-Key eintragen oder OAuth-Flow starten und bestaetigen.
  4. Status auf Active pruefen und mit einem Test-Call validieren.
2Was sind Dieters Funktionen (CEO, Task-Verteilung, Auto-Merge, Watchdog)?

Dieter ist dein Operator-Knoten: Er priorisiert, delegiert, ueberwacht Ergebnisse und kann bei sauberem Zustand automatische Merges triggern.

Screenshot Placeholder: Operator-Ansicht
Queue, Routing-Regeln, Merge-Gates, Watchdog-Status
  1. In Agents den Operator-Banner oeffnen und auf Steuern klicken.
  2. Im Tab Tasks Prioritaeten und Zielagenten kontrollieren.
  3. In den Operator-Einstellungen Auto-Merge nur mit Checks/Gates aktivieren.
  4. Watchdog-Checks beobachten und bei Fehlern Fallback/Neuverteilung starten.
3Wie gebe ich Dieter eine Seele (Einstellungen: Persoenlichkeit, Tonfall, Werte)?

Die "Seele" steckt in Prompt + Personality + SOUL/Werte-Memory. Damit laufen Entscheidungen konsistent ueber alle Aufgaben.

Screenshot Placeholder: Operator → Einstellungen
System Prompt, Personality, Soul/Werte Felder
  1. Auf Operator wechseln und den Tab Einstellungen oeffnen.
  2. System Prompt fuer Zielbild und Entscheidungslogik anpassen.
  3. Personality/Tonfall und SOUL/Werte konkret ausformulieren.
  4. Speichern und mit 2-3 realen Aufgaben pruefen, ob Verhalten stabil ist.
4Wie lege ich Tasks an (Kanban, Operator, API)?

Du kannst Tasks visuell im Kanban, operativ im Operator-Panel oder automatisiert ueber API erzeugen. Strukturierte Inputs verbessern das Routing.

Screenshot Placeholder: Kanban + Operator Task-Input + API Request Beispiel
  1. Kanban: Karte erstellen, Beschreibung, Deadline und Prioritaet setzen.
  2. Operator: Task direkt im Task-Tab eingeben und zuweisen.
  3. API: Task mit Kontext, Skill-Hinweis und Zielkriterium posten.
  4. Task-Status beobachten und bei Blockern frueh neu priorisieren.
5Wie werden Arbeiten verteilt (Skill-Routing, Auslastung, Fallback)?

Das System kombiniert Skill-Match, Verfuegbarkeit und Last. Wenn kein idealer Agent frei ist, greift eine definierte Fallback-Kette.

Screenshot Placeholder: Routing-Matrix mit Skills, Load und Fallback-Pfad
  1. Skill-Matrix im Operator laden und Agenten Skills sauber zuweisen.
  2. Auslastung in Agents/Monitor beobachten und Engpaesse markieren.
  3. Fallback-Regeln definieren (z. B. Team-Lead, Operator, Queue-Puffer).
  4. Regelmaessig Ergebnisse pruefen und Routing anhand Real-Performance nachschaerfen.

Tipp: Die gleichen Kurztexte werden als Mini-Help-Popup im Dashboard genutzt.
